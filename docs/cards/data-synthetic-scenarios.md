# Data card — synthetic airspace scenarios

Status: `validated` as a reproducible generator. **It is not a model of real
airspace** and no proportion in it should be read as one.

| | |
| --- | --- |
| Source | Generated by `src/acp/sim/`. No third-party data. |
| Generator version | `acp-gen-v1` |
| Simulator version | `acp-sim-v2` |
| Licence | This project's own output; MIT with the rest of the repository. |
| Reproducibility | Seed + version determine the output byte for byte. |

## Why there is no real data

Reviewed and rejected during M0; the analysis is
[ADR 0002](../adr/0002-synthetic-traffic-only.md). Briefly: the OpenSky Network
licence grants non-profit research use and does not grant redistribution, and
this repository's rules keep third-party data out of version control. Synthetic
traffic also provides **ground truth**, which is what makes the conflict-detection
metric non-circular.

## What a scenario contains

Aircraft with initial kinematics and an optional **plan** — timed commands to
turn, change level, change speed, or change transponder code — plus a sensor
model that degrades truth into observations.

**The plan is intent and it is never published.** The pipeline receives only
noisy position reports. This is the property that stops the trajectory model
being a trivial inversion of the generator.

## Families

| Family | Purpose | Manoeuvres | Levels | Background |
| --- | --- | --- | --- | --- |
| `NOMINAL` | Conflict-detection evaluation | 35% of the staged pair, one each | FL300–FL390 | 2–5, never manoeuvre |
| `TRAINING` | Trajectory model training and testing | 95% staged / 80% background, three each | FL300–FL390 | 4–7 |
| `SHIFTED` | Distribution-shift test | 90% / 70%, two each | FL240–FL290, FL400–FL410 | 5–9 |

`NOMINAL` is frozen. `eval/results/conflict_detection.md` records the SHA-256 of
the scenario set it scored, and `tests/unit/test_generator.py` recomputes that
fingerprint on every run. A change to generation that alters what `NOMINAL`
produces breaks the build rather than silently invalidating the report — which
it did, the first time this guard ran, catching a reordered random draw.

## Sensor model

| Parameter | Default | Basis |
| --- | --- | --- |
| Report interval | 1 s | Plausible for ADS-B |
| Position sigma | 30 m | Loosely representative, **not calibrated** |
| Altitude sigma | 25 ft | Loosely representative |
| Speed sigma | 2 kt | Loosely representative |
| Track sigma | 0.5° | Loosely representative |
| Dropout probability | 2% per report | Loosely representative |

Every one of these is a plausible operating point chosen by the author. None was
measured from a real feed.

## Known biases, stated so nobody reads a proportion off this data

- **Encounter density is wildly unrealistic.** `NOMINAL` stages a close encounter
  in essentially every scenario. Real airspace produces vastly fewer conflicts
  per flying hour, so the false-alerts-per-hour figure is a rate per hour of
  *deliberately adversarial* traffic and is not comparable to an operational one.
- **Manoeuvre density is unrealistic in `TRAINING` and `SHIFTED`.** Most aircraft
  manoeuvre several times in fifteen minutes. This exists because `NOMINAL` left
  a held-out set with seventeen turning samples.
- **Aircraft fly exactly.** Commanded turns and climbs are executed at constant
  rates with no overshoot, no wind, and no turbulence.
- **No airspace structure.** No airways, no sectors, no terrain, no procedures,
  no traffic flow. Aircraft are placed on random bearings.
- **Aircraft addresses are random**, not drawn from real registration blocks, so
  nothing in the data corresponds to a real aircraft.
- **Data association is free.** Every report carries an aircraft identifier, so
  the hardest part of real tracking is absent by construction.

## Regenerating

```
python eval/run_conflict_eval.py --scenarios 120 --seed 20260815 --include-committed
python -m acp.ml.train --scenarios 120 --seed 20260815
```

Nothing about a scenario set is stored; it is regenerated from the seed each
time. That is the whole point of committing a fingerprint rather than the data.
